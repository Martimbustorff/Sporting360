> **Nota antes do plano (para o Martim).**

> 2. Testar num telemóvel real exige um build nativo novo (entra o módulo `@react-native-firebase/messaging`). Esse build é o mesmo do redesign V7.1: não se faz um build só para o push, e o build só corre com o OK explícito do Martim.
> 3. Nada deste plano publica functions, regras ou builds. O envio fica desligado (`PUSH_ENABLED=false`) até o Martim o ligar no lançamento da V7.1.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pôr a funcionar as 5 preferências do ecrã Notificações com push real em iOS e Android (início do jogo, golos, abertura do MVP e notícias por tópicos FCM; lembrete de prognóstico por dispositivo), com o toque a abrir o ecrã certo.

**Architecture:** Servidor: um módulo `functions/src/push/` com os textos, o envio FCM (Admin SDK atrás de uma interface `PushSender`, mockada nos testes) e marcas idempotentes no Firestore (reclamar numa transação, enviar, libertar só se o envio falhar). O ticker ao vivo chama `dispatchMatchPushes` depois de cada `saveMatch` (início, golos, MVP, por estado e não por transição, por isso re-syncs e repetições não duplicam); o `newsSync` chama `pushLatestNews`; uma function agendada nova, `predictionReminderPush`, envia o lembrete aos tokens de `users/{uid}/devices`. App: `@react-native-firebase/messaging`; um `PushSetup` dentro de `(app)` pede a permissão depois do login, grava o token e sincroniza os tópicos com `users/{uid}.notificationPrefs` sempre que estas mudam; o toque abre `data.route`.

**Tech Stack:** Expo SDK 58, Expo Router, React Native Firebase 27.1.1 (API modular, `@react-native-firebase/messaging`), jest-expo e `@testing-library/react-native`; Cloud Functions Node 22 (firebase-functions 7, firebase-admin 13, `firebase-admin/messaging`), `@firebase/rules-unit-testing`, emuladores (`npm run test:emulator`).

**Spec:** `docs/superpowers/specs/2026-11-19-push-notifications-design.md` (aprovada pelo Martim a 19/11/2026). Ler também: `docs/superpowers/plans/2026-11-18-plan-5-lancamento.md` (Task 7, regras fase 2 e finais; Task 12, paragens) e `mobile/README.md` ("Paragens do Martim").

## Global Constraints

- Nunca `firebase deploy`, nunca `eas build` nem `eas submit`. Nenhuma task publica nada.
- Nenhum payload leva email, nome de utilizador ou uid. O único campo de `data` é `route`. Nomes de jogadores do Sporting e de clubes podem aparecer no texto.
- Textos da app, das notificações e dos documentos em pt-PT, sem travessões nem meias-riscas (`\u2014`, `\u2013`); identificadores de código em inglês.
- Cada envio do servidor é idempotente: marca reclamada numa transação antes de enviar; repetições, re-syncs e execuções seguidas nunca enviam duas vezes o mesmo evento.
- Tópicos exatamente `push_matchStart`, `push_goals`, `push_mvpOpen`, `push_news`. O lembrete de prognóstico não tem tópico: vai por token, só a dispositivos de utilizadores com `predictionReminder` ligado e sem `matchPredictions/{gameId}_{uid}`.
- Sem `notificationPrefs` no documento: tudo ligado (`DEFAULT_NOTIFICATION_PREFS`). Com o objeto presente, uma chave em falta conta como desligada (como `NotificationPrefsSchema`).
- Notícias: no máximo 2 por dia (dia de Lisboa). Só futebol do Sporting: nunca push de outras modalidades nem de golos do adversário.
- Permissão de notificações só depois do login (dentro de `(app)`), nunca no primeiro arranque nem no Welcome.
- `data.route` só nestas formas: `/jogo/{id}`, `/jogo/{id}?tab=mvp`, `/jogo/{id}?tab=prognostico`, `/noticias?id={slug}`.
- Functions novas no codebase `v2027`, região `europe-west1`, `timeZone: "Europe/Lisbon"`; cada function nova entra em `functions/scripts/deployLists.ts` e em `functions/test/unit/exports.test.ts`.
- Envio ligado por `PUSH_ENABLED` (`defineBoolean`, por omissão `false`, `false` nos dois `.env`). Com `false` nenhuma function envia nem escreve marcas.
- Testes nas suites existentes. Verificação de cada task das functions: `cd functions && npm run lint && npm test && npm run test:emulator`. Da app: `cd mobile && npm test && npm run typecheck && npm run check:tokens`.

## Review Focus

1. **O ticker vê o mesmo estado 4 vezes por minuto, e o `fixturesSync` re-sincroniza o jogo** → cada evento (início, cada golo, MVP) sai uma única vez. Teste na Task 3 (`dispatchMatchPushes` duas vezes com o mesmo jogo envia uma vez) e no `liveTicker.test.ts` (dois ticks seguidos, um envio).
2. **Golo anulado pelo VAR, autogolo de um jogador do Sporting, golo do adversário, lances com mais golos do que o resultado** → nunca push de golo do adversário e nunca mais pushes de golo do que golos do Sporting no resultado. Teste na Task 3.
3. **`PUSH_ENABLED` ligado (ou ticker publicado) a meio de um jogo, já na 2.ª parte e com golos antigos** → não sai "Começou o jogo" nem golos com mais de 15 minutos de jogo. Teste na Task 3.
4. **FCM falha (rede, quota) ou a function morre depois de enviar** → falha: a marca é libertada e a execução seguinte tenta outra vez; morte depois do envio: a marca fica e não se repete. Teste na Task 2.
5. **Duas contas no mesmo telemóvel (sair e entrar com outra)** → o lembrete da conta anterior deixa de chegar a este telemóvel e os tópicos passam a seguir as preferências da conta nova. Teste na Task 8.
